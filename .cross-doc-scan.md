# Cross-Document Consistency Scan

## Pair 1: heap/index.md ↔ kernel/index.md (Binary Exploitation)

- **Contradictions**: None. The two documents target different domains (userspace heap vs kernel exploitation). No version claims conflict.
- **Missed cross-references**: Both discuss freelist pointer obfuscation (heap: safe-linking in glibc 2.32+; kernel: SLAB_FREELIST_HARDEN). Neither references the other's technique, even though the mitigation concept is identical. The kernel doc's `msg_msg` cross-cache section (lines 654-867) covers heap-like exploitation patterns but does not point to the heap doc for foundational heap technique knowledge.
- **Integration gaps**: The kernel doc's "Heap Overflow via Size Mismatch" section (lines 290-298) discusses slab/ kmalloc exploitation but assumes reader familiarity with userspace heap concepts — no forward reference to heap/index.md for prerequisite knowledge.
- **Severity**: **Low**

## Pair 2: rsa/index.md ↔ lattice/index.md (Crypto)

- **Contradictions**: None. Technique descriptions are compatible.
- **Missed cross-references**: 
  - RSA doc has a full Boneh-Durfee implementation (lines 207-249) which is a lattice attack using LLL. It references `mimoo/RSA-and-LLL-attacks` but does NOT cross-reference the project's own `lattice/index.md`.
  - Lattice doc covers HNP, truncated LCG, LWE, subset-sum, Merkle-Hellman, and approximate GCD but NEVER mentions RSA or Boneh-Durfee as an application domain. The trigger section (line 5) says "many modular equations with a promise that hidden values are small" which applies to Boneh-Durfee, but no explicit mention.
  - Result: a reader of the lattice doc would not know that lattice attacks apply to RSA at all, and an RSA reader would not know the project has dedicated lattice documentation.
- **Integration gaps**: The two documents should cross-link. The RSA doc's Boneh-Durfee section should say "see also lattice/index.md for general lattice technique reference". The lattice doc should mention RSA as a key application area.
- **Severity**: **Medium**

## Pair 3: ecc/index.md ↔ rsa/index.md (Crypto)

- **Contradictions**: None. They cover separate primitives (ECC DLP vs RSA factoring).
- **Missed cross-references**:
  - ECC doc's MOV/Frey-Ruck attack (lines 170-205) transfers the ECDLP to a finite-field DLP in GF(p^k)*. This is a cross-primitive reduction, but the RSA doc is not referenced.
  - RSA doc does not mention ECC, MOV, or pairing-based attacks at all. Entirely self-contained.
  - The general discrete log problem appears in both: RSA's `gcd(e, phi) > 1` handling (line 176-189) and ECC's Pohlig-Hellman (lines 18-43). No cross-reference.
- **Integration gaps**: The MOV attack bridges ECC and finite-field DLP — this is the ideal place for a cross-link to RSA or a general DLP discussion. Currently absent.
- **Severity**: **Low-Medium**

## Pair 5: steganography/index.md ↔ network/index.md (Forensics)

- **MAJOR CONTENT OVERLAP**: 
  - Stego doc has a 160-line "Network Protocol Steganography" section (lines 380-538) covering TCP ISN LSB, IP ID field, HTTP cookie parity, DNS hex exfiltration, TLS ClientHello random LSB, ICMP payload extraction, and ICMP timing channels. This is a nearly complete parallel network forensics document.
  - Network doc has a smaller "Covert Channel Detection" section (lines 122-154) covering many of the same techniques: TCP flags, ICMP payload extraction, DNS query names, inter-packet timing.
  - NEITHER DOCUMENT REFERENCES THE OTHER. The stego doc's network section appears unaware that the network forensics doc exists, and vice versa.
- **Implementation conflict**: The stego doc uses full manual pcap parsing (lines 406-436) for IP ID extraction, while the network doc uses `tshark` for the same purpose. Different approaches to the same task.
- **Severity**: **High** — This is the most significant issue found. Duplicated content with zero cross-referencing. The network stego section should either be moved to the network forensics doc with a reference from stego, or both should be deduplicated with proper cross-links.

## Pair 7: model-attacks/index.md ↔ adversarial-ml/index.md (AI/ML)

- **Boundaries**: Mostly clear separation (model confidentiality/inversion/extraction vs evasion/robustness).
- **Missed cross-references**:
  - Neither document references the other. A reader arriving at either doc would not know the other exists.
  - Overlap in query-based attacks: model-attacks doc has "Model Extraction via Query API" (lines 398-516) with student distillation, while adversarial-ml doc has "Black-Box Evasion Attacks" (lines 277-361) with boundary attack, gradient estimation, and transfer attack. Both use the same API interaction pattern but for different goals. No cross-reference.
  - Overlap in shadow models: model-attacks uses shadow models for LiRA membership inference (lines 594-631), while adversarial-ml conceptually relates (adversarial training uses similar data splits).
  - Backdoor detection (adversarial-ml, lines 463-527) involves analyzing model weights, which is conceptually part of "model attacks." No reference.
  - Data poisoning (adversarial-ml, lines 409-461) involves modifying the model through training — this is a model integrity attack. No reference from model-attacks doc.
- **Severity**: **Medium** — The boundaries mostly hold, but the overlap areas (especially query-based attacks and shadow models) should cross-reference.
